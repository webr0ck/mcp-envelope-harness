# Python 3.12+ (the verifier requires it).

# The verifier is published from the reference implementation's repository and
# pulls in cryptography and jcs (RFC 8785 canonicalisation) itself.
#
# KNOWN GAP: it FLOORS them (cryptography>=44, jcs>=0.2.1) rather than pinning. The
# signer and the verifier must canonicalise identically, so a jcs skew between the
# two sides is an authenticity failure that surfaces as content_hash_mismatch - it
# looks exactly like an attack. Nothing here prevents that today.
#
# Pinned to a commit, not a branch: a clone today and a clone next month get the same
# verifier, and a push to that repo cannot silently replace the security-critical
# component here. tests/test_platform_interop.py checks the harness against the
# producer at this same revision, so the conformance target is fixed rather than moving.
#
# REMAINING GAP: a commit SHA is not a signed tag. This pins *which* code you get; it
# does not prove who wrote it. Signed tags plus a verified fingerprint would.
mcp-trust-verifier @ git+https://github.com/webr0ck/mcp-security-platform.git@583f229e4cb619bafd578de98b00e14126f4a181#subdirectory=sdk/mcp-trust-verifier
